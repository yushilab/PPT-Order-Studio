# 控制 Token 与制作成本

v0.1 不调用模型 API，因此本地 `ingest`、`validate`、`build`、`qa` 等命令不会自动产生模型 Token 费用。AI 读取上下文、生成文字或代码、理解页面截图，仍由所用应用或 API 消耗用量。OCR、图像生成和其他外部服务也应单独核算。

## 按阶段提供材料

| 阶段 | 提供给 AI 的材料 | 适合复用的内容 |
|---|---|---|
| 分析 | 当前文件片段、客户要求 | 未改变的提取结果 |
| 规划 | 全局摘要、关键事实、页数要求 | 来源索引和事实表 |
| 样张 | 代表页面内容、风格参考、必要素材 | 初始页面组件 |
| 全稿 | 当前几页、固定规范、相关事实 | 已确认风格和布局 |
| 修改 | 修改要求、受影响页和必要来源 | 未改变页面 |
| 检查 | 检查报告、实际页面预览 | 已检查且未变化的页面 |

`context --max-chars` 限定准备材料的字符长度。**字符数不等于 Token 数**，不同语言、模型和图片会采用不同计量方式。被截断的材料应回查，不能假设未出现的部分不存在。

固定规则和规范保持短且稳定；当前任务放在其后。已变更的原文、事实和规范需要重新读取。单纯把摘要存盘，并不会自动清除聊天仍携带的历史上下文；有条件时按阶段开启受控的新上下文。

## 记录实际用量

```bash
python -m pptstudio usage orders/client-a --stage sample --provider "所用平台" --model "实际模型" --input-tokens 8000 --output-tokens 1800 --cached-tokens 2000 --cost 0.12 --currency USD --note "平台显示的本次金额"
```

数值为命令格式示意，不是项目定价或成本估计。`cached-tokens` 是输入中的缓存部分，计算时不能再额外加到总输入。若平台报告缓存写入、推理、图像或其他计费项，按其实际口径在备注或外部账单中保留，不凭简单输入输出推导完整费用。

拿不到数据时只记已知信息：

```bash
python -m pptstudio usage orders/client-a --stage revise --provider "桌面AI" --note "平台未展示Token；本次人工配合约8分钟，修改S08"
```

未知不能填成零。订阅额度与 API 费用分别统计；图片理解用量与图片生成费用也不是同一个概念。API 缓存支持、时效和价格按所选平台及模型的实际说明核算。

## 每单更有用的指标

- 资料重复提取次数、原文回查次数。
- 样张修改轮数、整套风格重做次数。
- 每阶段实际输入输出、图像服务费用和重试。
- 你投入的人工时间、订单收入、外部素材费用。

先用两三个真实订单记录，再调整模型、批次和模板。多代理可以节省等待时间，也可能重复加载材料；只有独立且有明确边界的工作才适合并行。

参考：[OpenAI 缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)、[图像输入与生成计费边界](https://developers.openai.com/api/docs/guides/images-vision)。其他平台请采用其当前账单口径。
