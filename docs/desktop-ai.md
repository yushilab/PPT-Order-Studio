# 与桌面 AI 配合

项目可以作为 AI 可读的本地工作目录，也可以作为手动命令工具。采用哪种方式，取决于当前会话实际开放的文件、终端和工具权限。应用名称和付费订阅不能单独证明这些能力。

## 有本地文件和终端能力

将项目作为工作目录打开，把下面的启动提示交给 AI：

```text
请从当前项目的 AI_START_HERE.md 开始，并遵循 AGENTS.md。
先确认本会话能否读取和写入项目文件、运行终端命令。
如果能，按 docs/setup.md 在项目内准备 .venv，运行 doctor 和示例订单。
保留已有订单、人工精修稿和用户配置；根据实际检查结果处理缺项。
如果不能运行本地命令，切换到文档中的手动配合路线，列出我需要执行的具体命令。
这次先完成环境检查和可打开的示例草稿，报告实际生成的文件及验证结果。
不要替客户记录任何大纲、样张或最终确认。
```

后续真实订单可这样启动：

```text
请继续 orders/client-a 订单。先运行 status，再读取 brief.json。
客户资料已放入 sources。请增量导入，整理事实、来源及待确认问题，
根据页数要求提出逐页规划。先保存工作文件和大纲预览，供我确认内容。
不要开始制作整套；每个阶段只加载相关材料，缺少事实时回查原文。
```

支持仓库指令的代理可读取 `AGENTS.md`。项目还提供 `GEMINI.md` 入口，供支持该机制的 Gemini CLI 等环境使用；它不意味着 Gemini 的所有产品形态都会自动加载。可选项目 Skill 的安装见 `docs/setup.md`。

## 只能上传文件的 ChatGPT、豆包、Gemini 等会话

1. 在本机按安装文档准备环境，运行 `doctor`。
2. 用 `ingest` 和 `context` 准备当前阶段上下文。
3. 上传 `AI_START_HERE.md`、当前上下文文件；需要写 JSON 时再附 `docs/data-format.md` 和相关现有 JSON。
4. 请 AI 返回完整的新 JSON 或清晰的修改内容，手动保存到订单。
5. 本地运行 `validate`、`sample` 或 `build`，把真实错误输出或必要页面预览交给 AI 修正。
6. 客户确认后由操作者运行对应 `approve` 命令，继续下一阶段。

无需反复上传所有客户原件。上下文不足时按来源 ID 补充指定片段；文字排版需要视觉判断时，上传实际页面预览。

给聊天应用的处理提示：

```text
附件包含本次订单的当前阶段上下文、数据格式和现有内容文件。
请仅处理指定页面，保留真实来源 ID、数字单位和已确认风格。
返回可直接保存的完整 UTF-8 JSON，并说明需要我运行的本地验证命令。
如果信息不足，列明需要的来源片段；不要虚构事实。
你未获得本机执行能力时，不要声称已经保存文件、安装工具或生成 PPTX。
```

## 换电脑或换模型

把代码和该订单目录迁移过去，重新安装本机 `.venv`。让新会话从 `AI_START_HERE.md` 和 `status` 开始，按需读取当前阶段上下文，无需粘贴旧聊天全部历史。

模型切换后保持 `brief.json`、`deck.json`、`style.json` 和确认记录为项目状态依据。源文件和 CLI 输出比模型回忆更可靠。

若需要精确用量，将平台提供的实际数据录入 `usage`。平台不显示 Token 时记录未知及耗时；项目无法从桌面应用订阅余额可靠推算单次 Token。

参考：[OpenAI Skills](https://learn.chatgpt.com/docs/build-skills)、[Gemini CLI 的 GEMINI.md](https://geminicli.com/docs/cli/gemini-md/)。
