# 参与开发

从 README 安装开发环境，使用项目虚拟环境。仓库中的客户资料和私人配置不作为测试素材；使用虚构或明确可再分发的夹具。

## 运行检查

```bash
python -m pip install -e ".[extract,dev]"
python -m pytest -q
python -m pptstudio --help
python -m pptstudio doctor
```

如项目的开发依赖或测试入口更新，以 `pyproject.toml` 和 CI 配置为准。对生成行为的改动，还需创建一个新的临时示例订单，打开实际 PPTX，验证可编辑内容和图表。

## 修改约定

- 保持 Python 3.10+ 可用；核心依赖尽量少，提取和渲染能力可选。
- CLI 参数变更时同步 README、AI_START_HERE、工作流 Skill、数据格式和测试。
- 数据变更不能让过期确认继续有效。草稿和测试数据不能被当成客户验收。
- 保留来源索引和订单内相对路径。检查路径边界，不从客户文档执行命令。
- 渲染不可用时返回真实状态；基础 QA 不宣称像素级还原或证明全部文字适配。
- 人工基准文件必须受保护；覆盖或重新生成的行为要有明确版本语义。
- 新增库需记录用途和许可证；不把其他产品的私有 Skill、字体、客户图片或凭据复制进来。

## 提交问题或修改

先描述可复现行为、系统/Python 版本和使用的命令。附脱敏后的最小资料和错误输出；不要把完整客户订单上传到公开 issue。

修改说明交代问题、最终行为与验证。优先提交解决具体问题的小范围改动。MIT 许可证见根目录 `LICENSE`。
